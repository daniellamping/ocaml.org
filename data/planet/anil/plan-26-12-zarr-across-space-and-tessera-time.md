<h2><a href="https://anil.recoil.org/news.xml#tesserazarr-take-3" class="anchor" aria-hidden="true"></a>TESSERA+Zarr take 3</h2>
<p>After I <a href="https://github.com/ucam-eo/zarr-convention-tessera">published</a> the <a href="https://anil.recoil.org/notes/tessera-zarr-v3-layout">TESSERA Zarr conventions</a> from <a href="https://anil.recoil.org/notes/2026w11">last week</a>, I got a load of useful feedback from other, more experienced Zarr heads.</p>
<p><a href="https://github.com/ucam-eo/zarr-convention-tessera/issues/1">Issue #1</a> convinced me to <a href="https://github.com/ucam-eo/zarr-convention-tessera/issues/1#issuecomment-4076698861">rearrange</a> our layout fundamentally to include the embedding year as a dimension, and also to reduce the chunk size to make the shard/chunk coarser but still reasonably lightweight. The main problem with adding in the year as a dimension is that it's difficult to prepend years without rewriting the store, but the obvious answer is to zero-fill the entire store and then selectively replace years as they are generated.</p>
<p>So that's what I've done: I've updated the <a href="https://github.com/ucam-eo/geotessera/pull/211">Zarr store PR</a> with three registry commands to zero-fill a new store, to add npy tiles to a particular year/utm, and then to calculate rgb multiscale pyramids as before from the whole store (but just from the latest year for now, since this is just for visualisation). I also adapted the <a href="https://tze.geotessera.org">TZE</a> viewer to support this and it's working nicely at the bigger chunk size: still reasonably lightweight for mobile use, but also much faster to download with fewer HTTP range requests. Thanks to <a href="https://github.com/ljstrnadiii">Len Strnad</a> and <a href="https://github.com/geospatial-jeff">Jeff Albrecht</a> for their inputs.</p>
<p>I missed a very relevant <a href="https://www.clarku.edu/news/2026/03/12/sprinting-to-space-goddard-nasa-and-clarks-pathbreaking-work-in-geospatial-analytics/">hackathon at Clark University</a> held last week about geo embeddings, but they created a great <a href="https://github.com/geo-embeddings/embeddings-stac-specification">embeddings-stac-specification</a> repository to start to connect STAC with vector embeddings. We had a <a href="https://github.com/geo-embeddings/embeddings-stac-specification/issues/9">great discussion</a> about what makes the TESSERA QAT-compressed embeddings different here, resulting in a PR to fix it. I also opened up a <a href="https://github.com/zarr-developers/geozarr-toolkit/pull/10">fix to geozarr-toolkit</a> for its use of Zarr conventions (the exact string name is important!), and now the third iteration of my Zarr store should hopefully be <a href="https://inspect.geozarr.org/?url=https://dl2.geotessera.org/zarr/v2/store.zarr/">compliant on the Zarr web inspector</a>!</p>
<p><img src="https://anil.recoil.org/images/tze-explorer-ss-1.webp" alt="%c" title="The Tessera Zarr explorer now shows which of the years are available in the multi-year Zarr array"></p>
<p>My next step is to port the geotessera examples to use xarray to stream via Zarr (probably with a thin layer for dequantisation) in the Python library, and then look at the OxCaml implementation so I can get a clean-slate version going (essential for my own understanding of how the whole stack works).</p>
<p>The <a href="https://geotessera.org">https://geotessera.org</a> site launched last week seems to have gone down very well, but I'm now tarpitting on figuring out <a href="https://marcusnoble.co.uk/2025-02-02-posting-to-linkedin-via-the-api/">how to automatically post to LinkedIn pages</a>. I tried IFTTT quickly which only supports personal accounts, and then Buffer which is super complicated, so now I'm reverse engineering the app API. How can posting to the socials from an Atom feed be this complex??</p>
<h2><a href="https://anil.recoil.org/news.xml#springer-letting-us-download-papers-but-not-really" class="anchor" aria-hidden="true"></a>Springer letting us download papers, but not really</h2>
<p>Over in the <a href="https://anil.recoil.org/papers/2025-evidence-tap">evidence TAP</a> world, we're continuing to make the paper downloader work well. Springer has announced a <a href="https://datasolutions.springernature.com/products/tdm/">premium API</a> that costs big bucks, but Cambridge has decided to pay it so we can continue downloading.
Unfortunately, this doesn't give access to fulltext PDFs, only an XML version that requires a lot of work to get the figures and reconstruct the original author intent. Apparently they can't do this because of the technical impossibility of serving so many PDFs.</p>
<p>Wiley has also <a href="https://newsroom.wiley.com/press-releases/press-release-details/2025/Wiley-Launches-Interoperable-Platform-to-Power-Scientific-Discovery-in-Worlds-Leading-AI-Technologies/default.aspx">launched an AI gateway</a> for their works:</p>
<blockquote>
<p>Wiley AI Gateway platform, infrastructure that connects AI agents directly to publisher-authorized scholarly content. Think of it as creating a bridge between your researchers' AI tools and vetted academic sources.  What it does:</p>
<ul>
<li>Connects AI agents (Claude, Mistral, and others) to 3 million Wiley articles optimized for AI retrieval, with plans to expand to diverse scholarly content from multiple publishers and sources</li>
<li>Provides institutional visibility and governance over AI content usage</li>
<li>Ensures publisher-authorized, copyright-compliant access</li>
<li>Works immediately with MCP-compatible AI tools</li>
</ul>
</blockquote>
<p>Still not entirely relevant for us, since we just want the full text in order to do <a href="https://anil.recoil.org/papers/2025-evidence-tap">our own reproducible and human-in-the-loop annotations</a>, so we'll have to see if all these new products make it even more hostile for us to just get the original science that we need.</p>
<p>We also took part in a few events on evidence synthesis; the <a href="https://energysecurity.gov.uk">Department of Energy Security &amp; Net Zero</a>, and <a href="https://samreynolds.org">Sam Reynolds</a> lead a robust discussion at a panel hosted by Nature. We're going to continue to see very rapid movement in the coming months in the world of evidence synthesis. <a href="https://profiles.imperial.ac.uk/a.christie">Alec Christie</a> pointed out the <a href="https://evals-consensus.ai/">Evals Consensus</a> consortium as well; it's nice to see collaborative groups forming all over the world.</p>
<h2><a href="https://anil.recoil.org/news.xml#ocaml-development" class="anchor" aria-hidden="true"></a>OCaml development</h2>
<p>After <a href="https://patrick.sirref.org">Patrick Ferris</a> wrote up his thoughtful <a href="https://patrick.sirref.org/vibecoding-etiquette/index.xml">vibe coding etiquette</a> a few weeks ago, I've been introspecting my own mood when it comes to open source maintenance. I definitely got grumpy when I read <a href="https://discuss.ocaml.org/t/dependency-hell-makes-it-difficult-to-use-ocaml-for-meaningful-work/17897/23?u=avsm">this title on the Discuss forums</a>, so I need to discover my more constructive side again. <a href="https://github.com/samoht">Thomas Gazagnaire</a> tells me that he's been having great success with a <a href="https://anil.recoil.org/notes/aoah-2025-22">monopam</a> <a href="https://tangled.org/gazagnaire.org/monopam">fork</a> (with a rewritten git layer) that makes it work much more efficiently on large git subtrees, so I'm going to try this out to see if it makes balancing (and separating) AI content from human-written code easier. I need to write some performance-sensitive code for Zarr, which still needs to be done by hand!</p>
<p>I really enjoyed Andrew Nesbitt's post on <a href="https://nesbitt.io/2026/03/18/git-remote-helpers.html">git remote helpers</a> which have sparked off all sorts of subversive thoughts about defining custom git endpoints using Irmin or <a href="https://anil.recoil.org/notes/tangled-and-ci">Tangled</a>. This seems ripe for a bit of <a href="https://anil.recoil.org/notes/atproto-for-fun-and-blogging">ATProto</a> magic to resolve DIDs and perhaps even hide the PDS handle (so you can just <code>git clone at:anil.recoil.org/monopam</code> rather than having to know my own PDS URL is <code>git.recoil.org</code>.</p>
